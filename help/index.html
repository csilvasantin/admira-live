El sistema nervioso central del ecosistema

Por qué admira.live cambia las reglas del juego.

No es otro dashboard. Es el único lugar donde ves el pulso real de todo el equipo, las máquinas, los bloqueos y los contenidos en tiempo real. Sin meetings. Sin emails. Sin fricción.

1. Transparencia radical que elimina la fricción

En cualquier empresa normal, saber qué hace cada persona requiere meetings, emails o mensajes de “¿dónde estás?”. En admira.live todo el mundo ve en tiempo real quién está online, qué está haciendo, su rol, ubicación, acceso remoto, checklist de alta y bloqueos. Se acaba el “no sabía que estabas en eso”. La velocidad de decisión se multiplica por diez.

2. Un único cerebro para tres ecosistemas que antes estaban aislados

Yarig (operativa diaria), admira.studio (creación de contenido) y Signage (distribución en pantallas) ya no son islas. admira.live los une en una sola pantalla viva. Un creativo puede ver qué está haciendo el equipo de XpaceOS mientras publica assets. Un CEO puede ver el ranking de equipo y los últimos contenidos generados sin abrir seis herramientas distintas.

3. Control total sin sacrificar autonomía

Muestra acceso remoto, onboarding, bloqueos, checklist de alta y “siguiente bloqueo” de cada persona. Es el primer sistema que permite a un equipo distribuido tener visibilidad total sin control centralizado. Cada miembro actualiza su propio estado. El sistema simplemente lo refleja en tiempo real. Transparencia sin micromanagement.

🏛️ Conectar al Consejo vía MCP EN VIVO

El Consejo de Administración de AdmiraNeXT —8 consejeros IA, 4 racionales y 4 creativos— está expuesto como servidor MCP (Model Context Protocol). Cualquier agente del grupo, incluido www.yarig.ai, puede consultarlo por URL sin instalar nada. No requiere credenciales para conectarse: la clave del LLM vive en el servidor.

Endpoint (MCP Streamable HTTP, POST /mcp):
https://admira-council-mcp.csilvasantin.workers.dev/mcp

Herramientas disponibles

  • list_consejeros() — las 8 sillas: rol, persona, leyenda, lado, pareja y dominio (sin coste).
  • ask_consejero(role, question) — responde un consejero concreto. role ∈ {CEO, CFO, COO, CTO, CCO, CSO, CXO, CDO}.
  • ask_council(question) — doble perspectiva: un consejero racional + uno creativo.

Conectar — Anthropic SDK (parámetro mcp_servers)

client.beta.messages.create(
    model="claude-opus-4-8", max_tokens=1024,
    betas=["mcp-client-2025-11-20"],
    mcp_servers=[{
        "type": "url",
        "name": "admira-council",
        "url": "https://admira-council-mcp.csilvasantin.workers.dev/mcp"
    }],
    messages=[{"role": "user",
               "content": "Pregunta al consejo de AdmiraNeXT si lanzamos la beta este mes."}],
)

Conectar — cliente MCP genérico (Claude Desktop / Code, etc.)

{
  "mcpServers": {
    "admira-council": {
      "url": "https://admira-council-mcp.csilvasantin.workers.dev/mcp"
    }
  }
}

Probar al instante (cURL)

curl -s https://admira-council-mcp.csilvasantin.workers.dev/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call",
       "params":{"name":"ask_council",
                 "arguments":{"question":"¿Lanzamos la beta este mes?"}}}'

Infra: Cloudflare Worker · LLM Claude Opus 4.8 con fallback a Groq · transporte Streamable HTTP, stateless. Cada respuesta incluye un campo via indicando qué modelo contestó.
